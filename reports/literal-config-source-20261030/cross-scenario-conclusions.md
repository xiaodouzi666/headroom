## Compact one-candidate boundary

No inspected artifact establishes that the new one-candidate compact schema caused an incomplete multi-edit repair. It was introduced in R11 only. The s1 candidate was complete enough to run 20 optimizer updates. Its failure was numerical reference support. A candidate may contain all dependent setup and edits; one candidate is not one line or one source edit. The three historical positives need one substantive candidate each. This does not establish new live success on those cases.

## Remaining bounded-review coverage gaps

The current prerequisite helper only starts when a structured request has a non-null evidence_ref and a current/overall blocking scope. R9 s1/s4 requested only required_saving_gb with null refs; R9 s8 retained needs_more_info with no structured requests. Those histories would not enter that helper as written. A future coverage expansion would still need the same finite allowance, original facts, complete business validation and genuine blockers preserved; it cannot clear the flag on the host.
