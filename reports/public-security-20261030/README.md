## 已修复的问题

### P1：自定义脚本可能耗尽宿主机输出磁盘

原先 /out 是可写宿主机目录。持有有效令牌的脚本可以通过允许的输出操作持续写盘；CPU、RAM、模型额度和运行超时都不能构成磁盘总量硬限制。审计只运行了静态策略校验，没有执行填满宿主磁盘的攻击。

现在每次 Lab 使用独立 tmpfs 卷，**容量 512 MiB、inode 4096 均有硬限制**。目标容器不再获得可写宿主机输出挂载。一个使用已核验不可变镜像、无 GPU、禁网、只读挂载的 keeper 容器维持该卷；目标已停止并确认删除后，可信宿主程序才导出允许的普通采样文件。导出限制字节和条目数，拒绝符号链接、硬链接、稀疏文件、设备、FIFO、路径穿越与未知文件名。失败不发布部分结果，也不会把失败伪装成成功。

清理前核对本次创建的不可变容器 ID、镜像、只读 source 与输出卷身份。预先存在的同名容器或身份不明资源不会被盲目删除；无法确认清理则停止继续执行。正常结束、部分创建和 worker 中断后的恢复都有独立检查。

### P2：慢速上传在入队前缺少并发与总时限约束

Run 请求现在有 **3 个不等待的上传槽位和 30 秒总上传期限**。认证、提交开关和 Origin 检查先于读取 body；满槽返回 429，超时返回 408，取消、断线和超大请求释放槽位。原字节上限继续有效。

公网还在持久化 admission 之前检查存储，容量不足、锁忙或不安全时返回 503；不会因为反复拒绝的请求继续增长 admission 记录。准备源码和导出阶段在同一可信目录范围内再次持锁检查。公网监听器限制并发 64、连接等待队列 64、空闲 keep-alive 5 秒。它们是资源保护，不是完整 DDoS 防护。

## 存储保护的准确含义

| 约束 | 性质与范围 |
| --- | --- |
| 每次 Lab 512 MiB / 4096 inode | tmpfs 的硬写入边界；超限可导致采样失败 |
| 公网目录累计 16 GiB | 应用准入门槛，包含 jobs、上传源码、准备及失败记录；不是整个文件系统的硬配额 |
| 至少保留 8 GiB 空闲磁盘 | 每次有界宿主写入前检查，另为本次写入预留 1 GiB |
| 公网 scope 标记与短文件锁 | API、源码准备和导出共用；HTTP 不能关闭它 |
| 非公网 CLI | 保留每次 Lab 硬输出限制与空闲空间检查；不会因旧 runs 历史超过 16 GiB 而被新公网门槛永久拒绝 |

历史文件没有自动删除。超过 512 MiB 的快照、未知输出或不完整采样可能明确失败。其他宿主程序仍可能独立占用磁盘，不能把应用准入门槛描述成对整个服务器的空间保证。

## 审计边界与残余风险

只读源码审计未发现匿名 checkpoint 上传到宿主 torch.load、固定下载路径穿越或任意 pickle 对象执行的直接入口。下载使用 owner 校验、固定资产范围和逐级 NOFOLLOW；公开历史资料另受清单与哈希约束。该结论是限定范围的审查结果，不是无漏洞证明。

**Torch 2.5.1 仍有已确认的上游反序列化漏洞，尚未升级。** 当前找到的 torch.load 位于 Lab 容器里的自身 tensor offload 路径；Snapshot 导入采用受限的原始类型解码，且公网上传关闭。没有发现上述匿名直达宿主入口，不等于所有间接依赖、恶意脚本或原生算子都安全。需要单独完成兼容性验证后升级固定镜像，详见[依赖审计与官方公告](../public-dependency-audit-20261030/README.md)。

Docker 与 NVIDIA 驱动仍共享宿主内核，不能等同于敌对多租户虚拟机隔离。每次 Lab 派发前会重新检查 GPU：已有计算进程时拒绝执行，不杀其他项目进程；Headroom 锁不能阻止其他项目在预检后启动，所以仍不能保证零 GPU 竞争。

本轮未进行生产攻击、恶意 checkpoint 执行、全量依赖/源码渗透审计或新的完整模型验收。现有成功演示、历史失败、新思路实现范围请结合[从零测试与核心思路](从零测试与核心思路.md)阅读。
