# Snapshot quantitative grounding guard

This change is limited to uploaded Snapshot diagnosis. It adds checks after the existing shared schema/policy/evidence validator; the training repair flow and its validator are unchanged.

A bounded canonical table is prepended to the evidence, within the existing evidence token/byte budget. It gives each visible peak stack's exact byte count and decimal GB to nine places. Category aggregates appear only when every contributing reference is visible and their sum equals the analyzer's category total. Categories remain heuristics, not causal ground truth. A trimmed or hot-path-only measurement is unknown, never zero.

Each model root cause must match the sum of its **unique** cited visible peak rows within one byte, using Decimal arithmetic. Missing or duplicate measurement identities are rejected before that tolerance is considered. Cache/reserved gaps cannot borrow a stack reference to masquerade as its live allocation contribution; they can be discussed qualitatively. Narrative memory quantities (numeric GB/GiB/MB/MiB/KB/KiB/bytes and related units) are rejected in titles, notes, plan descriptions/risk and evidence requests. Structured expected_saving_gb remains an unverified prediction, not an observed reduction. The wording screen is narrow and is not a general natural-language truth checker.

On a grounding error, the original parsed diagnosis and new issue codes remain private, the public status is needs_human with no diagnosis or patch, and the model is not retried. Genuine needs_more_info is never cleared. No numeric output is silently corrected.

The saved s2 r2 diagnosis remains unchanged. A public, compact negative fixture retains its incorrect prose and numbers, with the original report hash. It proves that schema-valid output can still fail quantitative grounding. It does not convert the previous result into a repaired run or change any historical score.
