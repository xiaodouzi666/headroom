# One bounded Snapshot validation correction

FINAL_48H F3b (docs/FINAL_48H.md, lines 80–93) specifies an aggregate budget and a per-run allowance; it does not prohibit a validation correction inside that allowance. This change implements root's current authorization for at most one such correction. It does not create a new run, allocation or credit allowance.

The first response still goes through the Snapshot intent schema, host-derived quantities, complete Diagnosis validator and prose/quantity checks. A schema or semantic failure may receive one additional normal SDK request containing the original answer as untrusted data, bounded code/path feedback and the unchanged policy. Feedback explicitly forbids clearing real unknowns or disguising forbidden strategies by deleting requires_policy or relabelling numerics. Correct answers and genuine valid needs_more_info results are not retried.

Correction is eligible only for a real ClientResponse whose cost is known and finite and whose matching final ledger record is an HTTP 200 response with the expected model identity. Every attempt already recorded by that runtime must have known cost. Missing/unknown/upper-bound cost, transport/HTTP failures and filtered responses do not trigger correction. The second SDK request uses the same independent reserve/dispatch/accounting hooks. If its budget admission fails, no second transport dispatch occurs. If its answer still fails, the task stops.

Limits remain unchanged: HTTP retries 0, patch repairs 0, 2000 completion tokens, reasoning disabled, original per-run allowance and parent scope. There is no automatic whole-task restart or automatic third diagnosis call. Feedback length is bounded and still subject to the ordinary prompt/request and monetary admission checks.

Each attempt has its own private directory under diagnosis-attempts. Validly parsed original intents, quantity provenance and validation issues remain mode 600. Schema failures retain the existing bounded raw-response error receipt and issue paths. Correction feedback and the attempt summary are retained. Final compatible filenames refer to the final received/selected attempt; first answers are never rewritten. A budget/transport stop retains the earlier attempt and a stopped receipt.

The public quantity explanation now reads: “Memory sizes are calculated from the cited stacks in this reconstructed capture. The model supplies explanations. These figures do not prove the cause, savings, or a new GPU result. Groups can overlap and should not be added together.” Protocol identifiers remain machine-readable/private.

Validation: the three focused modules passed 74 tests in 6.79 seconds. After excluding content-filtered responses, all 11 tests in the correction module passed in 2.78 seconds. These groups overlap and must not be added as independent tests. Real SDK/router calls used explicit test-only MockTransport and an isolated BudgetLedger, proving one call on valid output, two independently admitted calls on invalid→correct, termination on invalid→invalid, budget rejection before additional dispatch, and no correction for HTTP/transport/unknown cost. All real network, credentials, production ledgers, GPU and service commands were denied by parent/spawn guards.

The initial log retains 73 passes and one failed existing cleanup assertion. A failed attempt-level error receipt initially bypassed the existing final error-persistence handler; this was fixed to preserve the required cleanup=false behavior. The assertion was not weakened. Ruff/format/diff checks and a scoped five-file secret scan passed. Independent read-only review found no remaining blocking issue.

This agent made no real model/GPU call, charge, service restart or public-enable action. Historical outputs and financial records were not changed. Add snapshot_feedback.py to retry source pins and prepare fresh proposals before live execution; older proposals are stale. Earlier no-correction reports describe their pinned historical versions, not this new bounded behavior.
