# Immutable external funding commitments

BudgetLedger.encumber(transfer_id, amount, receipt_sha256) creates one immutable donor funding commitment, not a run, attempt, provider call or actual charge. API returns the record dict. `committed_hold_usd` is a read-only Decimal property and `external_commitments()` returns copied audit rows.

Storage: budget_external_commitments(transfer_id TEXT PRIMARY KEY, amount_usd TEXT NOT NULL, receipt_sha256 TEXT NOT NULL UNIQUE, created_at TEXT NOT NULL). IDs and receipt hashes are validated and duplicate IDs or receipts are rejected. SQL triggers forbid UPDATE and DELETE. There is no refund, TTL or close_run release path.

Admission remains under the same BEGIN IMMEDIATE write transaction. Encumber requires positive finite global/daily authorization, the current UTC ledger day, no non-closed run, no unresolved/pending billing or halt, and sufficient total and daily capacity. Existing explicitly resolved conservative bounds retain their full charged amount and unknown actual; they are not turned into exact charges. All subsequent open_run and reserve commitments add the external holds to the normal existing totals. Every daily bound permanently counts every hold so date rollover cannot recycle donor funds. The target ledger is not credited or opened by this method; the caller must separately authorize and coordinate activation.

New cases verify both intended donor amounts (1.588313628 and 3.612190772), unchanged old actual/charged rows and snapshots, total/daily reserve admission, future-day hold retention, rejection of active/pending/unknown/halted states, retained conservative bounds, duplicate/SQL mutation protection, concurrent hold versus open_run admission, legacy no-table migration, and isolation from a separately funded target ledger. Additional cases reject stale UTC days and missing or zero global/daily authorization; the day check runs inside the same write transaction. Ruff check/format and git diff --check pass.

Only temporary offline fixture ledgers were mutated by tests. No donor or target production ledger was activated, no model/GPU call was made, and no allocation or judge binding was changed by this work. Receipt content and cross-ledger activation remain the parent accounting/controller responsibility.
